# Student Analytics AI Agent - A Complete Code Sample

A demo AI agent for analyzing student management data using **Claude Agent SDK** and **Amazon Bedrock AgentCore Runtime**.

This code sample demonstrate how to create a working prototpye end-to-end.

## 🎯 Overview

This demo project implements a student management analytics system with:
- **Claude Agent SDK** for multi-turn autonomous data analysis
- **Amazon Athena** for SQL query execution on S3 data lake
- **Amazon Bedrock AgentCore Runtime** for scalable agent hosting
- **Domain-specific agent skills** for business meaning of data

## 📊 Demo Database Schema

The system includes **2 denormalized analytics tables** optimized for AI agent queries. Each table is self-contained pre-aggregated metrics, making it easier for AI agent to generate and run queries consistently. In real world, these analytics tables and the tables meta data in `data/metadata/` should be generated by your ETL pipeline.

| Table | Records | Purpose |
|-------|---------|---------|
| `student_enrollment_analytics` | 50,000 | All enrollment-related questions (student, course, instructor, dept context) |
| `financial_summary_by_student` | 10,000 | Complete financial picture (payments, scholarships, balances) |


### Key Architecture Principles for analytics data structure
- ✅ **Denormalized** - All context in one table, minimal joins needed
- ✅ **Business-question focused** - Each table answers specific analytics categories
- ✅ **AI-optimized** - Agent generates simple SELECT queries without complex joins

See individual metadata files in `data/metadata/` for detailed column definitions, possible values, and statistics.

## 🚀 Quick Start

### Prerequisites

**Required:**
- **[uv](https://docs.astral.sh/uv/)**
- AWS account with configured credentials (`aws configure`)
- Claude Code 2.0.27+ (for local development and testing of the agent)

### 1. Install uv

```bash
# macOS and Linux
curl -LsSf https://astral.sh/uv/install.sh | sh

# Or via Homebrew (macOS)
brew install uv

# Verify installation
uv --version
```

### 2. Setup Project Environment

```bash
# Create virtual environment with Python 3.14
# uv will automatically download Python 3.14 if not installed
uv venv --python 3.14

# Activate the virtual environment
# On macOS/Linux:
source .venv/bin/activate

# Install all dependencies
uv pip install -r requirements.txt
```

### 3. Verify Installation

```bash
python scripts/verify_environment.py
```

### 4. Create S3 Bucket

```bash
# Create a unique S3 bucket for Athena results and data storage
BUCKET_NAME="student-analytics-agent-$(date +%s)"
aws s3 mb s3://${BUCKET_NAME} --region us-west-2

# Save bucket name for later use
export ATHENA_S3_BUCKET=${BUCKET_NAME}
```

This creates a uniquely named S3 bucket that will be used for:
- Storing uploaded CSV data
- Athena query results
- Temporary query execution outputs

### 5. Setup Athena Database

```bash
# Upload data and create tables using the bucket you just created
python scripts/setup_athena.py \
  --bucket ${ATHENA_S3_BUCKET} \
  --database student_analytics \
  --region us-west-2
```

### 6. Configure Environment

```bash
# Create .env file with your S3 bucket
cat > .env << EOF
# Athena Configuration
ATHENA_DATABASE=student_analytics
ATHENA_OUTPUT_LOCATION=s3://${ATHENA_S3_BUCKET}/athena-results/
AWS_REGION=us-west-2

# Claude Code Bedrock Configuration (REQUIRED for local agent execution)
CLAUDE_CODE_USE_BEDROCK=1

# Bedrock Model Configuration
ANTHROPIC_MODEL=global.anthropic.claude-sonnet-4-5-20250929-v1:0
ANTHROPIC_SMALL_FAST_MODEL=global.anthropic.claude-haiku-4-5-20251001-v1:0
EOF
```

**Notes:**
- The `.env` file is automatically, which will be loaded by the local agent using `python-dotenv`
- AWS credentials are automatically detected from your AWS CLI configuration (`~/.aws/credentials` or AWS SSO)
- No need to add AWS credentials to `.env` if you've already run `aws configure`

## 🚢 Deploying to AgentCore Runtime

### Step 1: Verify AgentCore CLI Installation

Verify AgentCore CLI is available:

```bash
# Verify installation
agentcore --help
```

### Step 2: Create IAM Role as the execution role for AgentCore Runtime

Run the automated setup script with your Athena S3 bucket:

```bash
python scripts/setup_agentcore_role.py --bucket ${ATHENA_S3_BUCKET}
```

This script will:

1. Create trust policy for AgentCore services
2. Create IAM role `StudentAnalyticsAgentCoreRole`
3. Create and attach comprehensive permissions policy
4. Output the role ARN for deployment

After successful execution, query and export the role ARN:

```bash
# Query AWS for the role ARN and export it
export AGENTCORE_ROLE_ARN=$(aws iam get-role --role-name StudentAnalyticsAgentCoreRole --query 'Role.Arn' --output text)

# Verify the export
echo "Role ARN: ${AGENTCORE_ROLE_ARN}"
```

**Key Permissions Explained:**
- **Athena**: Query execution, workgroup access, and data catalog operations
- **Glue**: Access to student_analytics database and tables for Athena metadata
- **S3**: Read/write access to Athena query results and data storage
- **Bedrock**: Invoke Claude Sonnet 4.5 and Haiku 4.5 global inference endpoints
- **CloudWatch Logs**: AgentCore runtime logging
- **AgentCore**: Runtime operations (agent invocation, session management)
- **ECR**: Pull container images for AgentCore runtime execution

### Step 3: Configure AgentCore Deployment

Now configure the AgentCore deployment with the IAM role you created:

```bash
agentcore configure \
  --entrypoint agent/agent_agentcore.py \
  --name student_analytics_agent \
  --execution-role ${AGENTCORE_ROLE_ARN} \
  --ecr auto \
  --deployment-type container \
  --requirements-file requirements.txt \
  --disable-memory \
  --region us-west-2 \
  --protocol HTTP
```

This creates `.bedrock_agentcore.yaml` with deployment configuration.

### Step 4: Test the Agent Code Locally

Before deploying the agent to AgentCore Runtime, test your agent locally to speed up the development cycle:

**Terminal 1 - Start Local Dev Server:**
```bash
# Start the local development server (runs on http://localhost:8080)
agentcore dev \
  --env ATHENA_DATABASE=student_analytics \
  --env ATHENA_OUTPUT_LOCATION=s3://${ATHENA_S3_BUCKET}/athena-results/ \
  --env AWS_REGION=us-west-2 \
  --env CLAUDE_CODE_USE_BEDROCK=1 \
  --env ANTHROPIC_MODEL=global.anthropic.claude-sonnet-4-5-20250929-v1:0 \
  --env ANTHROPIC_SMALL_FAST_MODEL=global.anthropic.claude-haiku-4-5-20251001-v1:0
```

This command:
- Starts the agent in development mode locally
- Hot-reloads on code changes
- Mimics the AgentCore Runtime environment to allow you test the agent locally without actually deploying it to AgentCore Runtime and improve the dev/testing cycle.

**Terminal 2 - Test the Agent:**
```bash
# Invoke the agent locally
python scripts/invoke_agentcore.py --dev "How many students are currently enrolled?"
```

The `--dev` flag tells the CLI to invoke your local development server instead of a deployed agent.

Once local testing succeeds, proceed to deploy to AgentCore Runtime.

### Step 5: Update Dockerfile

We need Claude Code installed in the container. We also need write permission to the results folders in the container. Repace the generated `.bedrock_agentcore/Dockerfile` with:

```dockerfile
FROM ghcr.io/astral-sh/uv:python3.14-bookworm-slim
WORKDIR /app

# All environment variables in one layer
ENV UV_SYSTEM_PYTHON=1 \
    UV_COMPILE_BYTECODE=1 \
    UV_NO_PROGRESS=1 \
    UV_PROJECT_ENVIRONMENT=/tmp/.venv \
    PYTHONUNBUFFERED=1 \
    DOCKER_CONTAINER=1 \
    AWS_REGION=us-west-2 \
    AWS_DEFAULT_REGION=us-west-2



COPY requirements.txt requirements.txt
# Install from requirements file
RUN uv pip install -r requirements.txt

RUN uv pip install aws-opentelemetry-distro==0.12.2

# Pre-create /tmp/.venv directory with proper permissions for uv
RUN mkdir -p /tmp/.venv && chmod 777 /tmp/.venv


# Signal that this is running in Docker for host binding logic
ENV DOCKER_CONTAINER=1

# Create non-root user
RUN useradd -m -u 1000 bedrock_agentcore

EXPOSE 9000
EXPOSE 8000
EXPOSE 8080

# Copy entire project with proper ownership
COPY --chown=bedrock_agentcore:bedrock_agentcore . .

# Switch to non-root user
USER bedrock_agentcore

# Use the full module path

CMD ["opentelemetry-instrument", "python", "-m", "agent.agent_agentcore"]

```

### Step 6: Launch to AgentCore

```bash
# Launch the agent with environment variables
agentcore launch \
  --env ATHENA_DATABASE=student_analytics \
  --env ATHENA_OUTPUT_LOCATION=s3://${ATHENA_S3_BUCKET}/athena-results/ \
  --env AWS_REGION=us-west-2 \
  --env CLAUDE_CODE_USE_BEDROCK=1 \
  --env ANTHROPIC_MODEL=global.anthropic.claude-sonnet-4-5-20250929-v1:0 \
  --env ANTHROPIC_SMALL_FAST_MODEL=global.anthropic.claude-haiku-4-5-20251001-v1:0
```

### Step 7: Invoke the Deployed Agent

```bash
python scripts/invoke_agentcore.py "How many students are currently enrolled?"
```

**Note:** Unlike `--dev` mode, this invokes the deployed agent on AgentCore Runtime in AWS.

### Step 8: Clean Up (Optional)

```bash
# Destroy the AgentCore deployment
agentcore destroy

# Optional: Delete the IAM role if no longer needed
aws iam delete-role-policy \
  --role-name StudentAnalyticsAgentCoreRole \
  --policy-name StudentAnalyticsAgentCorePolicy

aws iam delete-role \
  --role-name StudentAnalyticsAgentCoreRole

# Optional: Delete the S3 bucket if no longer needed
# WARNING: This will delete all data in the bucket
aws s3 rb s3://${ATHENA_S3_BUCKET} --force
```
